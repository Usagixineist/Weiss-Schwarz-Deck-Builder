# 维护与发布流程

本文件说明这个仓库（GitHub：`Usagixineist/Weiss-Schwarz-Deck-Builder`）的**日常更新、备份、发布新版本**该怎么做。

目标读者：以后接手的人（包括半年后的自己）。命令都可以直接复制到 PowerShell 里跑。

---

## 0. 先搞清楚三个位置

| 位置 | 路径 | 作用 | 进仓库？ |
| --- | --- | --- | --- |
| **游戏目录**（工作台） | `E:\Weiss Schwarz CH-0.6` | 日常开发、构建、运行；里面有 `_tools`（Roslyn 编译器）、`Weiss Schwarz_Data`、`StreamingAssets` 卡表 | ❌ 永不做 git 操作 |
| **仓库**（成品柜） | `E:\Weiss Schwarz CH-0.6\_repo` | 只放能发布的东西：源码、脚本、配置、插件 DLL，是游戏目录的一份**可发布副本** | ✅ 所有 git 操作都在这里 |
| **构建产物** | `DeckBuilder\build`、`dist`、`tests\dist`、`mod\plugin` | exe、zip、日志 | ❌ `.gitignore` 已排除 |

> ⚠️ **游戏目录里不要 `git init` / `git add` / `git commit`。**
> 那里是另一个仓库（卡表仓库）：`.gitignore` 是 `**`，remote 指向 gitcode，一旦误提交会把卡表数据推上去。

一句话记住方向：**代码在游戏目录改 → 构建/测试在游戏目录跑 → `sync-from-game.ps1` 把成品搬进 `_repo` → 在 `_repo` 里 commit/push。**

## 1. 日常更新（改代码 → 上线，约 2 分钟）

打开 PowerShell，先设两个变量（后面命令都假设有它们）：

```powershell
cd "E:\Weiss Schwarz CH-0.6\_repo"
$game = "E:\Weiss Schwarz CH-0.6"
```

### 第 1 步：在游戏目录改代码

改的是 `E:\Weiss Schwarz CH-0.6\DeckBuilder\` 下的东西：`src\`、`tests\`、`mod\src\`、`*.ps1`、`README.md`。

> 不要直接改 `_repo` 里的文件——下次同步会被游戏目录里的旧版本覆盖。

### 第 2 步：构建（先确认能编译过）

```powershell
# 主程序 -> 游戏目录 DeckBuilder\dist\WeissDeckBuilder.exe
powershell -NoProfile -ExecutionPolicy Bypass -File DeckBuilder\build.ps1 -GameRoot $game

# 同步插件 -> mod\plugin\WeissSchwarzDeckSync.dll，并装到 BepInEx\plugins
powershell -NoProfile -ExecutionPolicy Bypass -File DeckBuilder\mod\build.ps1 -GameRoot $game
```

- **必须带 `-GameRoot`**：仓库就在游戏目录里面，脚本默认用的"上一级"不等于游戏目录，会找不到 `_tools\roslyn\...\csc.exe`
- 只想编译不安装插件：`mod\build.ps1 -GameRoot $game -NoInstall`
- 报 `Deck Builder 正在运行（PID xxx）` → 先关掉 `WeissDeckBuilder.exe`（编译器不能覆盖正在运行的程序）
- 想构建完直接启动：`build.ps1 -GameRoot $game -Run`

### 第 3 步：跑测试

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File DeckBuilder\run-tests.ps1 -GameRoot $game -List              # 看有哪些分组
powershell -NoProfile -ExecutionPolicy Bypass -File DeckBuilder\run-tests.ps1 -GameRoot $game -Group import,export # 只跑相关分组
powershell -NoProfile -ExecutionPolicy Bypass -File DeckBuilder\run-tests.ps1 -GameRoot $game                   # 全跑
```

- 结果写在 `DeckBuilder\tests\test-results.txt`（已被 git 忽略，不会误提交）
- 源码没改动时脚本会复用上次编译的 `SmokeTests.exe`；`-Rebuild` 强制重编译
- 出现"**找不到游戏数据，依赖卡表的分组已跳过**"说明卡表没被找到 → 这种状态**不许发版**，先把 `-GameRoot` 指对或确认 `StreamingAssets` 在位
- 只改 UI 文案可以少跑几个分组，但**发版前必须全跑一次**

### 第 4 步：同步回仓库并检查改动

**最省事**：双击 `<游戏目录>\DeckBuilder\同步到仓库.cmd`。它调用 `sync-to-repo.ps1`，
按与 `tools\sync-from-game.ps1` 相同的规则同步，然后列出 `git status` 并把误入的构建产物标红。

| 命令 | 结果 |
| --- | --- |
| `同步到仓库.cmd` | 同步 + 列出改动（接着在 GitHub Desktop 里提交） |
| `同步到仓库.cmd -DryRun` | 只打印会复制什么 |
| `同步到仓库.cmd -Commit -Message "fix: ..."` | 同步 + 提交 |
| `同步到仓库.cmd -Commit -Push -Message "fix: ..."` | 同步 + 提交 + 推送 |

命令行等价写法：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\sync-from-game.ps1 -DryRun   # 先干跑，看会复制什么
powershell -NoProfile -ExecutionPolicy Bypass -File tools\sync-from-game.ps1           # 真同步（默认游戏目录 = 仓库的上一级）
git status --short
git diff --stat
```

同步范围只有三棵树：`DeckBuilder`、`BepInEx\plugins`、`BepInEx\config`；
自动跳过 `build`、`dist`、`plugin`、`dumps`、`test-results.txt`、`deck-sync-state.txt`。

**提交前自检**——`git status` 里出现下面任何一个，都说明有问题，先查原因再提交：

| 不该出现 | 原因 |
| --- | --- |
| `DeckBuilder/dist/`、`build/`、`tests/dist/`、`mod/plugin/` | 构建产物，靠 `.gitignore` 挡住；手动复制进去了就 `git rm --cached` |
| `*.log`、`test-results.txt`、`*.bak-*` | 日志/临时文件 |
| `data-root.txt` | 本机绝对路径，换机器就失效 |
| `BepInEx/core/*.dll`、`*.exe` | BepInEx 本体，按 LGPL 不分发，重装即可 |
| `Weiss Schwarz_Data/**`、`Decks/`、`MyCollocation/` | 游戏资源，仓库不含任何游戏数据 |
| `BepInEx/cache/` | 运行时缓存 |

### 第 5 步：提交并推送

```powershell
git add -A
git commit -m "fix: 卡组导出文件名含中文时乱码"
git push
git status -sb        # 期望：## main...origin/main（没有 [ahead 1]）
```

提交信息用前缀方便日后翻日志：

| 前缀 | 用途 | 例子 |
| --- | --- | --- |
| `feat:` | 新功能 | `feat: 支持按卡包过滤搜索结果` |
| `fix:` | 修 bug | `fix: 收藏数量为 0 时崩溃` |
| `docs:` | 只改文档 | `docs: 补充发版流程` |
| `chore:` | 杂项（脚本、忽略规则） | `chore: 同步脚本跳过 dumps` |
| `release:` | 发版提交 | `release: v1.1.0` |

不喜欢命令行也可以用 **GitHub Desktop**（仓库选 `_repo`，**不是**游戏目录）：
`Changes` → 勾要提交的文件 → `Summary (required)` 填摘要 → `Commit to main` → 右上角 `Push origin`。

## 2. 备份

### 2.1 三层备份，各管一件事

| 层级 | 手段 | 防什么 | 频率 |
| --- | --- | --- | --- |
| ① 远端 | 每次 `git push` 到 GitHub | 本机硬盘坏、误删文件 | 每次改动 |
| ② 里程碑 | 发版时打 tag（`v1.1.0`…）并 push | "想退回某个能用的版本" | 每版 |
| ③ 离线快照 | `git bundle` 单文件存到另一块盘 / U 盘 | GitHub 账号没了、仓库被误删 | 每周或每次发版后 |

> ✅ 现在 `main` 与 `origin/main` 已同步，tag `v1.0.0` 已在远端 —— ①② 已经生效。
> ③ 需要在**非 C/E 盘的物理介质**上做一次，才算真正有备份。

### 2.2 离线快照：`git bundle`（推荐）

一个文件装下全部分支、tag 和完整历史，能像普通仓库一样 clone 回来：

```powershell
cd "E:\Weiss Schwarz CH-0.6\_repo"
$stamp = Get-Date -Format 'yyyyMMdd-HHmm'
git bundle create "F:\backup\ws-repo-$stamp.bundle" --all
git bundle verify "F:\backup\ws-repo-$stamp.bundle"   # 显示 the bundle is okay / records a complete history
```

还原（任何装了 git 的机器）：

```powershell
git clone "F:\backup\ws-repo-20261116-1200.bundle" ws-restore
cd ws-restore
git tag              # 能看到 v1.0.0 等 tag
```

文件只有几 MB，比压缩整个 `.git` 稳（复制 `.git` 时若赶上 git 写文件会得到损坏的库）。

**替代方案**（也能用，但麻烦）：直接压缩 `_repo` 文件夹（含隐藏的 `.git`）到别的盘，恢复时解压即可。

### 2.3 游戏目录里"删了就重建不出来"的东西

仓库**不含任何游戏数据**，下面这些必须单独备份：

| 内容 | 位置 |
| --- | --- |
| 自己的卡组 | `<游戏目录>\Weiss Schwarz_Data\StreamingAssets\Decks\*.txt` |
| 我的收藏 | `<游戏目录>\Weiss Schwarz_Data\StreamingAssets\MyCollocation\*.txt` |
| 暂存卡组（5 个固定槽） | `<游戏目录>\Weiss Schwarz_Data\StreamingAssets\DeckDrafts\` |
| 游戏内卡组库 | 注册表 `HKCU\Software\Blake Thoennes\Weiss Schwarz` |
| 插件本机配置 | `<游戏目录>\BepInEx\config\*.cfg` |

```powershell
$src = "E:\Weiss Schwarz CH-0.6\Weiss Schwarz_Data\StreamingAssets"
$dst = "F:\backup\ws-data-$(Get-Date -Format yyyyMMdd)"
foreach ($d in @('Decks', 'MyCollocation', 'DeckDrafts')) {
    if (Test-Path "$src\$d") { robocopy "$src\$d" "$dst\$d" /E /NFL /NDL /NJH /NJS /NP | Out-Null }
}
reg export "HKCU\Software\Blake Thoennes\Weiss Schwarz" "F:\backup\ws-registry.reg" /y
```

恢复时把 `Decks`、`MyCollocation`、`DeckDrafts` 拷回原位置，注册表文件双击导入（先**退出游戏**）。
插件同步基线 `BepInEx\plugins\WeissSchwarzDeckSync\deck-sync-state.txt` 不用备份——删掉只会触发一次全量对比。

### 2.4 不需要备份 / 不要提交

`DeckBuilder\build`、`dist`、`tests\dist`、`mod\plugin`、`BepInEx\cache`、`LogOutput.log`、
`BepInEx\core`（BepInEx 本体）、`_tools`（编译器，随游戏目录）、`Output\`（导出的卡图/PDF，随时可重生成）。

以上全都能由源码 + 脚本重新生成，备份它们只是浪费空间。

## 3. 发布新版本

### 3.1 版本号规则

`DeckBuilder\version.txt` 只有一行（现在是 `1.0.0`），`package.ps1` 读它决定 zip 名字。

| 改了什么 | 版本号 | 例子 |
| --- | --- | --- |
| 只修 bug / 文案 | 第三位 +1 | `1.0.1` |
| 加功能但保持兼容 | 第二位 +1 | `1.1.0` |
| 破坏性改动（配置项改名、数据格式变） | 第一位 +1 | `2.0.0` |

**tag 名 = `v` + 版本号**（`v1.1.0`），必须和 `version.txt` 一致，否则用户不知道下载哪个 zip 对哪个 tag。

### 3.2 改版本号 → 构建 → 全量测试 → 打包

```powershell
cd "E:\Weiss Schwarz CH-0.6\_repo"
$game = "E:\Weiss Schwarz CH-0.6"

# 1) 改版本号（先改游戏目录里那份，再同步进仓库）
notepad "E:\Weiss Schwarz CH-0.6\DeckBuilder\version.txt"
powershell -NoProfile -ExecutionPolicy Bypass -File tools\sync-from-game.ps1

# 2) 构建 + 全量测试（发版必须全跑，不许跳过卡表分组）
powershell -NoProfile -ExecutionPolicy Bypass -File DeckBuilder\build.ps1 -GameRoot $game
powershell -NoProfile -ExecutionPolicy Bypass -File DeckBuilder\mod\build.ps1 -GameRoot $game
powershell -NoProfile -ExecutionPolicy Bypass -File DeckBuilder\run-tests.ps1 -GameRoot $game

# 3) 打包（产物在仓库 DeckBuilder\dist，已被 git 忽略）
powershell -NoProfile -ExecutionPolicy Bypass -File DeckBuilder\package.ps1
```

产物：`_repo\DeckBuilder\dist\WeissDeckBuilder-<版本>.zip`（约 5.6 MB），解开就是 `DeckBuilder\` 文件夹，丢进游戏目录即可用。

`package.ps1` 的常用开关：

| 开关 | 作用 |
| --- | --- |
| `-Version 1.1.0-beta1` | 临时版本号，不改 `version.txt`（测试包用） |
| `-IncludeSource` | 连 `src\`、`tests\`、`lib\`、`mod\src` 一起打包（给想自己编译的人） |
| `-NoDocs` | 不含 `docs\` 截图（README 图会显示不出来，一般不用） |
| `-KeepStaging` | 保留 `build\package` 里的中间目录，便于核对内容 |
| `-OutputPath D:\xx.zip` | 自定义输出位置 |

打包脚本自带**自检**：压缩包里若出现 `data-root.txt`、`build/`、`tests/`、`*.log`、`test-results.txt`、`*.bak-*`，或缺少 `dist/WeissDeckBuilder.exe`，会直接报错退出。**报错就是红灯，不要绕过。**

> 也可以在游戏目录打包（产物在游戏目录的 `dist`）：
> `powershell -NoProfile -ExecutionPolicy Bypass -File "E:\Weiss Schwarz CH-0.6\DeckBuilder\package.ps1"`
> 两种做法等价，区别只是 zip 放在哪。归档到 Release 时别拿错：认准版本号。

### 3.3 提交、打 tag、推送

```powershell
git add -A
git commit -m "release: v1.1.0"
git tag -a v1.1.0 -m "Weiss Schwarz 卡组构建器 v1.1.0"
git push                 # 推提交
git push origin v1.1.0   # 推 tag（不推 tag，网页上就选不到它）
git --no-pager tag       # 复核本地 tag 列表
```

现有 tag：`v1.0.0`（已在远端）。

### 3.4 在 GitHub 建 Release（Desktop 不能传附件，用网页）

入口：仓库菜单 `Repository` → `View on GitHub`，或直接打开
`https://github.com/Usagixineist/Weiss-Schwarz-Deck-Builder/releases/new`

| 页面英文 | 中文含义 | 你填什么 |
| --- | --- | --- |
| `Choose a tag` | 选择标签 | 选刚推上去的 `v1.1.0` |
| `Target: main` | 目标分支 | 保持 `main` |
| `Release title` | 发布标题 | `v1.1.0 — 一句话说明` |
| `Describe this release` | 发布说明 | 新增 / 修复 / 升级注意 |
| `Attach binaries by dropping them here or selecting them.` | 附件区 | 拖入 `WeissDeckBuilder-1.1.0.zip` |
| `Set as the latest release` | 设为最新版 | ✅ 勾上 |
| `This is a pre-release` | 这是预发布 | 测试包才勾 |
| `Publish release` | 发布 | 最后点它 |

发布说明建议模板：

```markdown
## 新增
- ...

## 修复
- ...

## 升级方式
下载 `WeissDeckBuilder-1.1.0.zip`，解压覆盖到游戏目录的 `DeckBuilder\`，再双击 `安装.cmd`。
卡组、收藏、配置不会被覆盖。
```

### 3.5 发布后自检（2 分钟）

1. 无痕窗口下载 zip，解开确认结构：`DeckBuilder\dist\WeissDeckBuilder.exe`、`安装.cmd`、`README.md`、`mod\plugin\WeissSchwarzDeckSync.dll`、`docs\*.png`
2. 解压到**临时目录**试装：`powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1 -Preview`（只演练不写入）
3. 双击 `DeckBuilder\dist\WeissDeckBuilder.exe`，确认能读到卡表（找不到会提示，见 README「程序怎么找卡表」）
4. 回网页确认 tag / 附件名 / 文件名三者版本号一致

### 3.6 发错了怎么办

| 情况 | 处理 |
| --- | --- |
| 说明文字写错 | Release 页面 `Edit release` 改完保存，**不要**删掉重发（链接会变） |
| 附件传错 / 想换包 | `Edit release` → 删旧附件 → 传新附件；tag 不动，版本号也不改 |
| tag 打错（还没发 Release） | `git tag -d v1.1.0` + `git push origin :refs/tags/v1.1.0`，改完重新打 |
| 代码有严重 bug | 修好发 `1.1.1`（用户能看懂"新版修了"）；旧 Release 可勾 `This is a pre-release` 降级 |
| 想撤回某个提交 | `git revert <commit>` 再发新版；**不要** `git push --force` 改写已发布的历史 |

## 4. 常见问题

| 现象（原文） | 原因 | 处理 |
| --- | --- | --- |
| `Roslyn csc not found: ...\_tools\roslyn\...` | 少了 `-GameRoot`，或游戏目录写错 | `-GameRoot "E:\Weiss Schwarz CH-0.6"` |
| `Deck Builder 正在运行（PID 1234）` | `WeissDeckBuilder.exe` 没关 | 关掉程序再构建 |
| `不是游戏目录（缺少 Weiss Schwarz.exe）` | `sync-from-game.ps1` 的默认上一级不对 | `-GameRoot "E:\Weiss Schwarz CH-0.6"` |
| `找不到游戏数据，依赖卡表的分组已跳过` | `StreamingAssets` 没找到 | 检查 `-GameRoot`；此状态不许发版 |
| `git status` 里冒出 `dist/xxx.exe` | 手动复制过构建产物 | `git rm --cached -r DeckBuilder/dist` 后确认 `.gitignore` 生效，别 `git add -A` 硬推 |
| `push` 又要求登录 / `Authentication failed` | 凭据过期 | `git credential-manager github login`；或 GitHub Desktop → `File` → `Options…` → `Accounts` → `Sign out` 再登录 |
| `Failed to connect to github.com` | 网络 / 代理 | 开代理后：`git config --global http.proxy http://127.0.0.1:7890`；取消：`git config --global --unset http.proxy` |
| GitHub 网页上传附件报 `Yowza, that file is too big!` | 单文件超 100 MB | 本项目 zip 约 5.6 MB，正常遇不到；真超了就用 `-IncludeSource` 分开打或改分卷 |
| 代码明明改了，GitHub 上没变 | 忘了同步 / 提交 / 推送 | 按第 1 节第 4、5 步重走一遍 |
| GitHub Desktop 显示 `No local changes` 但仓库确实改过 | Desktop 里选的是**游戏目录**那个仓库 | 左侧仓库列表切到 `_repo`（路径结束于 `\_repo`） |
| 打包报 `缺少打包必需的文件` | 没先构建 | 先跑 `build.ps1` 和 `mod\build.ps1` |

## 5. 检查清单

### 每次改动（提交前逐条打勾）

- [ ] 改的是**游戏目录**里的文件，不是 `_repo`
- [ ] `DeckBuilder\build.ps1 -GameRoot $game` 通过
- [ ] `DeckBuilder\mod\build.ps1 -GameRoot $game` 通过（没改插件可跳过）
- [ ] 相关测试分组通过（`run-tests.ps1 -Group ...`）
- [ ] 已经跑过 `tools\sync-from-game.ps1` 或双击了 `DeckBuilder\同步到仓库.cmd`（不是手动复制）
- [ ] `git status` 里没有 `dist/`、`build/`、`*.log`、`data-root.txt`、`BepInEx/cache`
- [ ] 提交信息带前缀（`feat:` / `fix:` / `docs:` / `chore:`）
- [ ] `git push` 后 `git status -sb` 显示 `## main...origin/main`，没有 `[ahead 1]`

### 每次发版（多出来的项）

- [ ] `version.txt`、tag 名、zip 文件名三者版本号一致
- [ ] 全量测试通过，且**没有**出现"依赖卡表的分组已跳过"
- [ ] `package.ps1` 自检通过，zip 约 5.6 MB
- [ ] 提交已推、tag 已推（`git push origin vX.Y.Z`）
- [ ] Release 附件就是这个 zip，标题/说明写清升级方式
- [ ] 干净环境（无痕窗口）下载解压能跑，`install.ps1 -Preview` 正常
- [ ] `DeckBuilder\README.md` / 根 `README.md` 已更新对应功能说明
- [ ] 做过一次 `git bundle` 离线快照

### 每月一次

- [ ] `git bundle create` 到另一块盘 / U 盘
- [ ] 备份 `StreamingAssets\Decks`、`MyCollocation`、`DeckDrafts` 与注册表
- [ ] `git fetch --prune` 后看一眼远端分支和 tag 有没有意外变动
